# The curation review queue is git pull requests, not an admin UI

The core-app spec planned an "admin review queue" for Pending interactions mined from drug labels and interaction databases. We chose to have the curation pipeline write Pending interactions as YAML into `data/` and have a person review them as an ordinary pull request instead. Curated data already lives in git and every change is already a reviewable diff, so a PR gives us the queue, the audit trail and the approval step without accounts, auth, a write API or a second store to keep in sync with the YAML. A Rejected interaction is merged as a file with `status: rejected` rather than deleted, so the pipeline never proposes it again. Moving to an admin UI later would mean building auth and a write path and moving review history out of git.
